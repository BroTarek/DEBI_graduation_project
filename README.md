# YouTube Clone - Database Design Documentation

## Project Overview
This project presents a comprehensive database design for a YouTube-like video sharing platform. The design captures the core functionality required to build a scalable video hosting service, including user management, video handling, social interactions, and content moderation.

## Purpose
The goal of this project is to create a robust, normalized database schema that can support all essential features of a modern video sharing platform. The design focuses on:

- **Scalability**: Supporting millions of users and videos
- **Data Integrity**: Maintaining relationships between entities
- **Extensibility**: Easy addition of new features
- **Performance**: Optimized for common queries and operations

## Key Features Supported

### 1. User Management
- User registration and authentication
- Profile management with avatars
- Channel creation and customization
- Subscription system for following channels

### 2. Video Management
- Video upload and metadata storage
- Multiple privacy settings (public, private, unlisted)
- Video categorization and tagging
- Multiple video renditions for different quality levels
- Subtitle/caption support

### 3. Social Interactions
- Comments with nested replies
- Like/dislike system for videos and comments
- Community posts from channels
- Real-time notifications

### 4. User Engagement
- Watch history tracking
- Search history
- Custom playlists (like "Watch Later")
- Personalized subscriptions feed

### 5. Content Moderation
- User reporting system
- Admin moderation actions
- Report tracking and resolution

## Database Schema Structure

### Core Entities

| Entity | Description | Key Fields |
|--------|-------------|------------|
| **User** | Platform users with authentication | email, passwordHash, displayName |
| **Channel** | Content creator channels | name, description, subscriberCount |
| **Video** | Video content uploaded by channels | title, duration, privacyStatus |
| **Comment** | User comments on videos | content, likeCount, replyCount |

### Interaction Entities

| Entity | Description | Key Fields |
|--------|-------------|------------|
| **VideoReaction** | Tracks likes/dislikes on videos | type (like/dislike) |
| **CommentReaction** | Likes on comments | type (like only) |
| **Subscription** | Channel follows | userId, channelId |
| **Playlist** | User-created video collections | name, visibility |
| **PlaylistItem** | Videos within playlists | position |
| **WatchHistory** | User viewing history | watchDuration, lastPosition |
| **SearchHistory** | User search queries | query, timestamp |

### Content Enhancement Entities

| Entity | Description | Key Fields |
|--------|-------------|------------|
| **VideoCategory** | Predefined video categories | name (Gaming, Music, etc.) |
| **VideoTag** | Tags for discovery | name |
| **VideoRendition** | Transcoded video versions | resolution, bitrate, codec |
| **Subtitle** | Caption files | language, autoGenerated |
| **ChannelPost** | Community posts | content, mediaUrls |

### Moderation Entities

| Entity | Description | Key Fields |
|--------|-------------|------------|
| **Report** | User reports on content | entityType, reason, status |
| **ModerationAction** | Admin actions on reports | action, notes |

## Entity Relationships

### User → Channel
- One-to-many: A user can own multiple channels
- Channels are the content publishing entities

### Channel → Video
- One-to-many: Channels upload multiple videos
- Videos belong to exactly one channel

### Video → Comment
- One-to-many: Videos have multiple comments
- Supports nested replies via self-referential relationship

### User → Reactions
- One-to-many: Users can like/dislike multiple videos
- Unique constraint prevents duplicate reactions

### User → Subscriptions
- One-to-many: Users can subscribe to multiple channels
- Creates the subscription feed functionality

### User → Playlists
- One-to-many: Users create multiple playlists
- Playlist items maintain order with position field

### User → History
- One-to-many: Tracks watch and search history
- Timestamps for chronological ordering

### User → Reports
- One-to-many: Users can report inappropriate content
- Tracks report status for moderation workflow
